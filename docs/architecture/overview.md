# Architecture overview

flust is an Expo app for iOS and Android, written in TypeScript. Everything runs on the device: there is no backend and no network service.

## Routing

Navigation uses Expo Router. Each file in `src/app/` is a screen and `_layout.tsx` files define navigators. The root layout (`src/app/_layout.tsx`) is a stack whose screens are protected by the session: the onboarding is the only screen until a journey exists, and the tabs, the emergency screen and the lapse screen only exist afterwards. See [0012 Onboarding flow](../decisions/0012-onboarding-flow.md).

`app.json` enables two experiments:

- `typedRoutes`: route paths are type-checked.
- `reactCompiler`: components are memoized by the React Compiler, so manual `useMemo` and `useCallback` are rarely needed.

## Source layout

`src/app/` contains routes only. Logic lives outside the routes, in layers whose imports are enforced by lint (see [Conventions](../development/conventions.md#layers)):

| Folder          | Purpose                                               |
| --------------- | ----------------------------------------------------- |
| `src/app/`      | Screens and navigators                                |
| `src/features/` | Screens and hooks: one folder per feature, and shared |
| `src/domain/`   | Pure logic: streaks, ranks, dates                     |
| `src/data/`     | Storage and crypto                                    |
| `src/ui/`       | Shared components and theme                           |
| `src/lib/`      | Shared infrastructure such as i18n                    |
| `modules/`      | Native modules                                        |
| `assets/`       | Brand and images                                      |

Folders are created when their first code lands.

## Native modules

Reminders on Android use `modules/flust-reminders`, a Kotlin module that sets local alarms and shows notifications, so the app links no Firebase code ([0021](../decisions/0021-local-notifications.md)). iOS uses `expo-notifications`.

`modules/flust-privacy`, in Swift and Kotlin, reads a clock that keeps running while the phone sleeps, for the wait between unlock attempts and the relock after time away ([0023](../decisions/0023-app-lock.md), [0024](../decisions/0024-lock-wait.md)). On Android, it also sets `FLAG_SECURE` on the app's window as the activity is created, in place of `expo-screen-capture`, which is not linked there ([0025](../decisions/0025-screen-privacy.md)), and asks the keyboard not to learn what is typed in text fields ([0036](../decisions/0036-keyboard-learning.md)).

The content filter of V0.2 will need platform APIs that Expo does not expose: a Swift module using the Screen Time API on iOS, and a Kotlin module providing VPN-based DNS filtering on Android ([0033](../decisions/0033-android-filter-network-access.md)). Neither exists yet.

They live in `modules/` as local Expo modules. Any native code requires a development build, Expo Go cannot load it.

`ios/` and `android/` are generated by prebuild and are not committed. Native configuration goes through `app.json` and config plugins.

## Local storage

User data is stored on the device only and encrypted at rest. Encryption keys are held by the platform keystores (Keychain on iOS, Android Keystore on Android). See [0001 Local-first](../decisions/0001-local-first.md) and the [threat model](../security/threat-model.md).

The data lives in one SQLCipher database opened by `src/data/open-storage.ts`, which also handles missing keys, damaged files and schema migrations. `LaunchGate`, at the top of the root layout, counts the launch and opens safe mode after two launches in a row that never reached a first screen ([0028](../decisions/0028-error-boundaries-and-safe-mode.md)). Below it, `StorageGate` opens the database before any screen is shown and provides the repositories to features through `useStorage()`. `SessionGate`, below it, loads the journey, the chosen language and the onboarding draft before the splash screen hides. See [0011 Encrypted SQLite storage](../decisions/0011-encrypted-sqlite-storage.md).

## Errors

Each route exports an Expo Router `ErrorBoundary`, and the root layout exports one for the gates. Fallbacks show static text only and record what they caught in the error log, an AES-GCM file with its own key, outside the database, so safe mode can read it. Global JS errors and, in release builds, unhandled promise rejections are recorded too. See [0028](../decisions/0028-error-boundaries-and-safe-mode.md) and [0029](../decisions/0029-local-error-log.md).
