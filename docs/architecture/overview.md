# Architecture overview

flust is an Expo app for iOS and Android, written in TypeScript. Everything runs on the device: there is no backend and no network service.

## Routing

Navigation uses Expo Router. Each file in `src/app/` is a screen and `_layout.tsx` files define navigators. The root layout (`src/app/_layout.tsx`) is a stack whose screens are protected by the session: the onboarding is the only screen until a journey exists, and the tabs and the emergency screen only exist afterwards. See [0012 Onboarding flow](../decisions/0012-onboarding-flow.md).

`app.json` enables two experiments:

- `typedRoutes`: route paths are type-checked.
- `reactCompiler`: components are memoized by the React Compiler, so manual `useMemo` and `useCallback` are rarely needed.

## Source layout

`src/app/` contains routes only. Logic lives outside the routes, in layers whose imports are enforced by lint (see [Conventions](../development/conventions.md#layers)):

| Folder          | Purpose                                                 |
| --------------- | ------------------------------------------------------- |
| `src/app/`      | Screens and navigators                                  |
| `src/features/` | Screens and hooks: journal, streak, emergency, blocking |
| `src/domain/`   | Pure logic: streaks, ranks, dates                       |
| `src/data/`     | Storage and crypto                                      |
| `src/ui/`       | Shared components and theme                             |
| `src/lib/`      | Shared infrastructure such as i18n                      |
| `modules/`      | Native modules                                          |
| `assets/`       | Brand and images                                        |

Folders are created when their first code lands.

## Native modules

Content blocking needs platform APIs that Expo does not expose:

- iOS: Swift module using the Screen Time API.
- Android: Kotlin module providing VPN-based filtering.

They live in `modules/` as local Expo modules. Any native code requires a development build, Expo Go cannot load it.

`ios/` and `android/` are generated by prebuild and are not committed. Native configuration goes through `app.json` and config plugins.

## Local storage

User data is stored on the device only and encrypted at rest. Encryption keys are held by the platform keystores (Keychain on iOS, Android Keystore on Android). See [0001 Local-first](../decisions/0001-local-first.md) and the [threat model](../security/threat-model.md).

The data lives in one SQLCipher database opened by `src/data/open-storage.ts`, which also handles missing keys, damaged files and schema migrations. `StorageGate` in the root layout opens it before any screen is shown and provides the repositories to features through `useStorage()`. `SessionGate`, below it, loads the journey, the chosen language and the onboarding draft before the splash screen hides. See [0011 Encrypted SQLite storage](../decisions/0011-encrypted-sqlite-storage.md).
